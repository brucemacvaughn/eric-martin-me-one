# AGENTS.md — Eric Martin / Me One website

Instructions for any AI agent working in this repo. Read this before making changes.

## What this is

The official website for **Eric Martin**, also known as **Me One** and **MC Eric** — founding
member of Technotronic, co-writer of *Pump Up The Jam, The Album*, owner of Musicated Records.
The site's job is to get promoters to book the DJ set.

Plain HTML, CSS and JavaScript. **No framework, no build step, no package.json, no npm install.**
Served directly by GitHub Pages from `main` at the repository root.

Live: `www.ericmartinmusic.club`

**Eric Martin is the owner and the person you are usually working for. He is not a developer.**
Explain what you changed in plain language. Never assume he will read code to understand you.
If he asks for something that would break the site, say so plainly instead of doing it.

## Hard rules

1. **Relative paths only.** `assets/styles.css`, never `/assets/styles.css`. Absolute paths break
   the site when it is served from a subdirectory.

2. **Never add a cache-busting query string.** `?v=20260526...` was removed on purpose. It had to
   be bumped by hand in five files on every change, and repeatedly made people think a change had
   not deployed. GitHub Pages caches for about ten minutes and self-heals. Do not reintroduce it.

3. **The nav and footer are NOT in the HTML files.** They are generated by `assets/main.js` from
   the `PAGES` array near the top. To add, rename or reorder a menu item, edit that array once.
   Editing the HTML will do nothing.

4. **Do not reformat, minify or "tidy" the HTML.** Keep the existing indentation and line breaks.
   Collapsing sections onto long lines makes every future diff unreadable.

5. **Do not introduce a framework, bundler, package manager or build step.** If a task seems to
   need one, stop and say so instead.

6. **Never force-push and never rewrite history.** More than one person commits here.

7. **Do not edit `*.backup.html`.** They are local safety copies and are not part of the site.

## Tour dates — the section Eric uses most

All shows live in the `GIGS` array at the top of `assets/gigs.js`. There is a plain-English
comment block above it explaining the format. Copy the shape of an existing line exactly:

```js
{ date: "2026-11-17", name: "Haddaway & Friends", location: "Oberhausen, Germany", role: "DJ — Technotronic Set" },
```

- `date` is always `YYYY-MM-DD`.
- Past dates disappear from the site automatically the day after they happen. Do not delete them
  by hand unless a show is cancelled.
- Order does not matter. They sort themselves.
- Dates in a future year automatically show the year on the site.

**This file is JavaScript, and that makes it fragile.** A single missing comma, quote or brace
will silently blank the entire dates section — no error message, the list just vanishes. After
editing it, re-read the whole array and check every line ends with `},` and every text value is
wrapped in double quotes. Apostrophes inside a name are fine (`"We Luv The 90's"`); double quotes
inside a name are not.

## Forms

The booking, production and newsletter forms post to **FormSubmit** (`formsubmit.co`), configured
in `FORM_ENDPOINTS` at the top of `assets/main.js`. They deliver to Eric's inbox.

Do not change the endpoints, and do not remove the hidden `_subject`, `_template` or `_captcha`
inputs from the forms — `_captcha=false` in particular is what stops the submission breaking.

## Brand — do not drift

- Teal `#5FC9D6`, background `#0a0a0c`, accent `#cdd4d6`. **Do not introduce new colours.**
- Album, EP and single titles are set in `<em>` italics, never in quote marks.
- Asset filenames are kebab-case: `hey-listen-this.jpg`, `live-mic.jpg`.
- Section headings are sentence case. The pillar sub-headings are the deliberate exception.

## Images

You cannot generate or edit image files. If a task needs a new photo, a different crop, or a
regenerated favicon, say so and ask Eric to supply the file.

The banner at the top of the booking page is a placeholder live shot (`assets/live-mic.jpg`).
When real crowd photography arrives, **swap the `src` only** — the framing, height and gradient
are all handled in CSS by `.page-bleed`.

## Publishing

Commit to `main`. GitHub Pages redeploys automatically, usually within a minute. There is nothing
to build and nothing to run. If a change does not appear, wait ten minutes for the cache before
assuming anything is wrong.
